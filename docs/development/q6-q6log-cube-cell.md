# Q6 权重 x Q6 对数量化激活胞元说明

本文档单独说明 [cube_q6_q6log_arch.svg](../../cube_q6_q6log_arch.svg) 这张图，不和 `run.sh` 的使用说明混排。

## 1. 文档范围

这份文档描述的是一个面向硬件实现的、简化后的 cube 胞元数据通路，用来承载当前实验里的这一组数值语义：

- 权重按 `Q6 + BF16 block scale` 处理
- 激活按 `Q6` 对数量化码 + `BF16 block scale` 处理
- 软件侧 `step` 可以灵活配置；当前这张图落实的是 `step ∈ {1,2,3,4}`，并且在一次矩阵乘过程中保持固定
- 每个块在进入 `psum` 之前乘一次 `BF16 scale`

这份文档不描述当前 CPU 内核的真实执行流水。

## 2. 与当前软件实现的关系

当前仓库中的 `SIM_Q4Q6` 仍然是 replay-only 的 QDQ 仿真路径，不是原生量化 matmul 内核：

- 软件先把 `src0`、`src1` 做分块量化再立刻反量化
- 反量化后的数据进入 `BF16` staging buffer
- 最终仍然走当前 canonical CPU `BF16` dot 路径

所以，这张图表达的是“当前量化语义如果映射成一个简单硬件胞元，应当长什么样”，而不是“当前 `ggml-cpu` 已经这样实现”。

## 3. 对应的软件开关

这张图对应的软件侧开关是：

- `SIM_Q4Q6=1`：启用独立的低比特 replay 路径
- `SIM_Q4Q6_SRC1_QMODE=2`：激活侧使用对数量化 `Q6-exp + BF16 block scale`
- `SIM_Q4Q6_SRC1_LOG_STEP=<正整数>`：控制指数步长，图中的 `step_cfg` 对应的就是这个参数

需要注意：软件开关仍然允许任意正整数 `step`，但当前这张 SVG 已经进一步收敛成 `step` 只取 `1 / 2 / 3 / 4` 时的最优硬件结构。

其中：

- `step=1` 表示最粗的指数梯度
- `step` 变大时，指数刻度变密
- 但在一次 GEMM 内部，`step_cfg` 不变化，只会在不同实验运行之间变化

## 4. 图中胞元的边界假设

这张图刻意只保留最基本、最直接的 `Q6 x Q6` 通道，不考虑原始 `F8 x F8` 图中更复杂的共享逻辑：

- 不考虑 `BF16` 扩展预留的跨 lane 互连
- 不考虑 `F32` / `BF16` `psum` 复用
- 不考虑为了兼容其他数据类型而存在的复用选择器
- 只比较 lane 前端的乘加数据通路

换句话说，这是一张“怎么简单怎么来”的胞元图。

## 5. 单 lane 数据通路

图里每一路 lane 都拆成了下面几个明确阶段。

### 5.1 激活码拆分

激活输入按块进入 lane，单个元素携带：

- 符号位 `sign`
- 幅值编码 `|qa|`

图中的“符号 / 幅值拆分”模块就是把这两个量分离出来，供后续译码使用。

### 5.2 形成 `d = 31 - |qa|`

对数激活的幅值不直接用 `|qa|` 参与乘法，而是先形成：

$$
d = 31 - |q_a|
$$

这样做的意义是把“越大的码值对应越大的幅度”重新表达为“离最大级还差多少步”。

### 5.3 `4` 模式专用分解

为了和当前 SVG 对齐，这里不再把这一级画成“通用 `Q6log` 译码 ROM”，而是画成 `4` 模式专用分解器。

它接收：

- `d`
- `step_cfg`

输出：

- `shift`
- `frac_sel`

它对应的软件语义是：

$$
\alpha = 2^{-d / step}
$$

但硬件不需要在线做除法、取模、对数或指数运算，而是直接把 `(d, step_cfg)` 映射成一个“移位量 + 细粒度常数因子”。

更具体地说，可以把 `d` 分解成：

$$
d = m \cdot step + r, \quad 0 \le r < step
$$

于是：

$$
\alpha = 2^{-d / step} = 2^{-m} \cdot 2^{-r / step}
$$

从一般数学语义上看，仍然可以把它理解成：

- `shift = m`，对应粗粒度的二进制移位
- `frac = 2^{-r / step}`，对应移位之间的细粒度残差因子

这也是为什么 `frac` 被称为“小常数”。它不是一个运行时自由变化的浮点数，而是：

- 在一次 GEMM 内，`step_cfg` 固定
- `r` 的取值范围只有 `0 .. step-1`
- 因此 `frac` 只会从一个很小的有限集合中取值

但在当前这张图里，`step` 已经限制为 `1 / 2 / 3 / 4`，所以硬件不再输出“真实 `frac` 数值”，而只输出一个很小的 `frac_sel`，再交给后一级去选择乘积表项。

例如，如果不做这个限制，当 `step = 5` 时，`frac` 会有这 5 个候选值：

$$
\{1, 2^{-1/5}, 2^{-2/5}, 2^{-3/5}, 2^{-4/5}\}
$$

而在当前图里，对应的硬件落地方式已经变成：

- `step = 1 / 2 / 4`：直接位切片生成 `shift` 和 `frac_sel`
- `step = 3`：用一个很小的 `32` 项 LUT 生成 `shift` 和 `frac_sel`

### 5.4 `192` 项乘积查表

权重侧输入是一个 `Q6` 有符号整数：

$$
q_w \in [-31, 31]
$$

在更一般的表达里，后一级可以写成：

$$
q_w \times frac
$$

但当前这张图没有再画这个通用小乘法器，而是进一步落实成：

$$
(frac_{sel}, |q_w|) \rightarrow \text{product LUT}
$$

也就是用 `frac_sel` 和 `|q_w|` 直接索引一个很小的乘积查找表。

这里的“小常数”有两个含义：

- 一是它来自一个很小的查表集合，而不是任意实数
- 二是它的数值范围总在 `(0.5, 1]` 之间，不会放大 `q_w`

因为：

$$
frac = 2^{-r / step}, \quad 0 \le r < step
$$

所以最小值出现在 `r = step - 1`：

$$
frac_{min} = 2^{-(step-1)/step} > 0.5
$$

这意味着 `frac` 非常适合用一个无符号定点常数来表示，而不是用完整浮点格式表示。

最直接的实现方式有两种：

1. 把 `frac` 存成一个小位宽无符号定点数，例如 `frac_num = round(frac \cdot 2^B)`，然后计算

$$
q_w \times frac \approx (q_w \times frac_{num}) >> B
$$

2. 当 `step` 的可选值很少时，直接把每个 `frac` 做成常数乘网络，利用移位加法实现

如果不对 `step` 做限制，这里最自然的实现是“输出一个小位宽定点常数，再做一个很窄的定点乘法”。

但在当前这张图里，因为 `step` 已经限制到 `1 / 2 / 3 / 4`，所以这一级已经进一步收敛成了 `192` 项乘积查表，不再保留独立乘法器。

如果要给一个很自然的实现建议，可以这样看：

- `q_w` 是 6 bit 有符号整数
- `frac` 可以实现成 `8` 到 `10` bit 左右的无符号定点数
- 乘法器本体因此只是一个 `6 x (8~10)` bit 的小乘法器，或者等价的移位加法网络

这和原 `F8 x F8` 浮点乘法完全不是一个量级的复杂度。

这也是相对原 `F8 x F8` 结构能省面积和功耗的关键原因之一。

这里“简单”主要体现在四点：

- 不需要比较指数、对齐尾数、规格化结果
- 不需要处理 `NaN`、`Inf`、非规格化数等浮点特殊情况
- 参与乘法的一个操作数只有 6 bit，另一个操作数来自很小的常数集合
- 当 `step = 1` 时，`frac = 1` 恒成立，这个乘法器可以直接旁路掉

#### 当 `step` 只允许 `1 / 2 / 3 / 4` 时的最优实现

如果 `step` 被限制为 `1 / 2 / 3 / 4` 这四种模式，那么最优实现通常不再是“通用 `ROM + 定点乘法器`”，而是“4 模式专用译码 + 常数选择 + 极小乘法 / 查表网络”。

最关键的原因是，这时所有可能出现的 `frac` 只有 6 个不同的值：

$$
\left\{1, 2^{-1/2}, 2^{-1/3}, 2^{-2/3}, 2^{-1/4}, 2^{-3/4}\right\}
$$

也就是说，硬件根本不需要支持任意 `frac`，只需要支持一个 6 项常数集合。

推荐的最优做法是：

- 用 `2 bit` 的 `step_mode` 编码四种模式
- 先求 `d = 31 - |qa|`
- 不输出“真实 `frac` 数值”，而是只输出一个很小的 `frac_sel`
- `frac_sel` 再去驱动一个极小的常数乘网络，或者直接驱动一个乘积查找表

四种模式里，`shift` 和 `frac_sel` 的生成可以这样做：

- `step = 1`：`shift = d`，`frac_sel = 0`，对应常数 `1`
- `step = 2`：`shift = d >> 1`，`frac_sel = d[0]`
- `step = 4`：`shift = d >> 2`，`frac_sel = d[1:0]`
- `step = 3`：这是唯一不适合直接位切片的模式，推荐用一个很小的 `32` 项 LUT，把 `d` 直接映射到 `{shift, frac_sel}`

这样处理以后，`step = 1 / 2 / 4` 都不需要真正的除法或取模逻辑，只有 `step = 3` 需要一个极小的专用表。

如果目标是最高 PPA，推荐把 `frac` 的实现继续往前推一步，直接改成“乘积查表”，而不是保留一个小乘法器。

具体做法是：

- 保留 `q_w` 的符号位单独处理
- 对 `|q_w|` 使用 `0..31` 的绝对值索引
- 用 `(frac_sel, |q_w|)` 直接查表得到 `|q_w| \times frac` 的定点结果

这样乘法器可以完全消失，变成一个非常小的 ROM / PLA。

因为：

- `frac` 只有 `6` 种
- `|q_w|` 只有 `32` 种

所以总表项只有：

$$
6 \times 32 = 192
$$

即使每项用 `12` bit 左右的定点数来存，规模也只有几千 bit，通常比一个通用乘法器更省面积，也更省动态功耗。

如果给出一个很实用的格式建议：

- 偏向 PPA 最优：把 `|q_w| \times frac` 存成 `Q5.7` 无符号定点
- 偏向精度更稳：存成 `Q5.8` 无符号定点
- 符号单独在后面折叠成补码，不必把符号位存进查找表

这两个格式的原因很直接：

- `|q_w| \times frac` 的范围是 `[0, 31]`
- `5` 个整数位就够覆盖 `0..31`
- `7` 到 `8` 个小数位通常已经足够表达这 6 个常数的差别

从 PPA 角度看，最优结构可以概括成：

1. `step_mode` 在 GEMM 开始前锁存，整次 GEMM 不变
2. `d` 经过 4 模式专用分解器得到 `shift` 和 `frac_sel`
3. `(frac_sel, |q_w|)` 进入一个 `192` 项的小乘积表
4. 查表结果做符号折叠
5. 再执行 `>> shift`
6. 最后进入整数规约和块末 `BF16 scale-late`

这比“通用小乘法器 + 通用译码”的结构更优，原因有四个：

- `step = 1 / 2 / 4` 可以直接用位切片产生 `shift` 和 `frac_sel`
- `step = 3` 的特殊性被局部化到一个很小的 `d -> {shift, frac_sel}` LUT
- `q_w x frac` 被完全改写成小查表，不再需要乘法器
- `step_mode` 在整次 GEMM 固定，未使用模式可以静态关断或时钟门控

因此，如果目标明确是 `step ∈ {1, 2, 3, 4}` 下的最高效率和最优 PPA，推荐优先级如下：

1. 最优方案：`4` 模式专用分解 + `192` 项乘积查表 + 符号折叠 + 移位
2. 次优方案：`4` 模式专用分解 + `frac_sel` 常数网络 + 一个极小定点乘法器
3. 不推荐方案：保留通用 `frac_num` 乘法器，再去支持任意 `step`

### 5.5 符号折叠 / 补码

激活的符号不会再单独保留到后端大位宽数据通路里，而是在这里直接折叠进结果：

- 正数直接通过
- 负数做补码取反加一

图中的“符号折叠 / 补码”就是在表达这个动作。

### 5.6 `>> shift`

`Q6log` 译码给出的 `shift` 对应粗粒度指数缩放。

因此 lane 不需要做完整浮点对齐，只需要一个移位器：

$$
(q_w \times frac) >> shift
$$

这一步把原先 `F8 x F8` 乘法器后面那一串复杂的 mantissa/exponent 对齐，压缩成了“译码 + 移位”的组合。

### 5.7 `INT RADD16` 块内求和

每个块里的若干项先在整数域内求和，图中画成 `INT RADD16`。

这里强调的是两个点：

- 进入块内规约之前，数据仍然是窄整数通路
- 只有块内整数和形成之后，才进入块末的 scale-late 阶段

## 6. 块末 `BF16 scale-late`

图里没有把 `scale` 混进每一次逐元素乘法，而是采用块末统一乘一次的方式。

### 6.1 四路 `scale_ij`

对于两路特征和两路权重构成的四路胞元，四个 scale 分别是：

- `scale0 = scale_a0 * scale_w0`
- `scale2 = scale_a1 * scale_w0`
- `scale1 = scale_a0 * scale_w1`
- `scale3 = scale_a1 * scale_w1`

这四个 scale 在图里分别进入对应 lane 的 `scale_ij reg`。

### 6.2 为什么放到块末

块末统一乘一次 `BF16 scale` 的好处是：

- 逐元素数据通路保持窄整数化
- `BF16` 乘法不是每个元素触发一次，而是每个块触发一次
- 关键路径可以和整数规约路径部分解耦

因此图里的块末阶段画成：

$$
psum_{int} \times scale_{ij}
$$

然后再写入每路自己的 `psum`。

## 7. 时序理解

这张图对应的时序假设是：

- 一周期进入一个量化块
- 在这一块内部，lane 完成译码、窄乘、符号折叠、移位和整数规约
- 块末再做一次 `BF16 scale-late`
- 之后写入对应的 `psum`

如果时序紧张，图中建议的最直接打拍点有两个：

- `Q6log 译码ROM` 后
- `>> shift` 前后

这样不会改变数值语义，只是把关键路径拆短。

## 8. 相对 `F8 x F8` 的结构差异

和原图相比，最本质的变化不是“把浮点格式从 8 bit 改成 6 bit”，而是“把乘法核心从小浮点乘法器，换成对数量化码译码器”。

原 `F8 x F8` lane 前端的主角是：

- `Booth`
- `CSA`
- `TADD4`
- 浮点对齐网络

现在这张 `Q6 x Q6log` 图里，lane 前端的主角变成了：

- `Q6log` 译码 ROM
- 小常数乘
- 符号折叠
- 移位器
- 窄整数规约

因此这不是“缩小版 F8 乘法器”，而是另一种更贴近对数量化语义的通路结构。

## 9. PPA 方向性结论

这里的 PPA 只比较 lane 前端，不比较原图里那些复用的 `BF16/F32` 累加网络。

### 9.1 面积

面积下降的主要来源是：

- 去掉 `Booth / CSA / TADD4` 主树
- 去掉大部分浮点对齐网络

新增代价主要是：

- `Q6log` 译码 ROM
- 小常数乘法器
- 移位器

总体上，lane 前端面积是下降的。

### 9.2 功耗

功耗改善通常会比面积更明显，原因是：

- 浮点部分积树的大翻转活动消失
- 通道内主要变成窄整数运算
- `BF16` 乘法降成“每块一次”而不是“每元素一次”

所以动态功耗是这条路最稳定的收益点。

### 9.3 时序

这条路的关键路径更可能落在：

$$
ROM \rightarrow const\text{-}mul \rightarrow shift \rightarrow reduction
$$

通常这会比一个小浮点乘法树更容易做流水和收敛频率。

因此，若只看 lane 前端，频率更容易收敛。

## 10. 总结

这张图表达的核心结论是：

对于当前的 `Q6` 权重和 `Q6log` 激活，最简单的硬件胞元不应该继续沿用 `F8 x F8` 的浮点乘法器骨架，而应该改成：

- 译码 ROM
- 小常数乘
- 符号折叠
- 移位
- 窄整数累加
- 块末 `BF16 scale-late`

也就是说，真正的结构变化来自“数值语义变了”，而不只是“位宽变小了”。
